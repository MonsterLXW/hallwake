02 · the problem
The problem

Booth mini games die in thirty seconds

Forgettable

A passerby tries once, feels nothing, walks on. Nothing pulls them back to the leaderboard.

Unfair horror

Random scares punish first-timers and veterans alike. Dying to dice reads as a broken game, not a hard one.

Undemoable

Unscripted games can't be filmed reliably — every take of the demo video is a different roll.

If the player can't learn, the booth can't win.

03 · the answer
The answer

Learnable horror, not luck

Every scare is scripted to a fixed door number and telegraphed with a readable tell. No unreadable RNG. Survival is knowledge — and the leaderboard rewards knowledge, not dice.

attract▸door▸tell▸counterplay▸death▸checkpoint retry▸run card▸leaderboard▸attract

Same corridor, every run

The 24-door table is authored data. The sim adds no randomness — a player who saw it once beats it every time.

Checkpoints, not punishment

Six checkpoint doors. Death costs seconds, never the whole run — first-timers keep coming back.

Reproducible on camera

Deterministic events make the demo video identical take-after-take. The manifesto is also the film plan.

06 · the identity
The night porter's kit

Bone is information. Color is danger.

A diegetic HUD, not an overlay

  • Stenciled door numeral, bottom-right — turns chalk-red for one beat on a TALLY tell
  • Door log as a ruled ledger, top-left — the TALLY counterplay surface, always on
  • Brass oil tube, bottom-left — ticks at 20% / 60%, 1 Hz alarm pulse below 20%
  • Tell glyphs center-bottom: slit · hollow ring · four-stroke tally · flame outline

Identity rules, enforced

  • Three voices: signage / instruments / typewriter — no text in the wrong voice
  • Radius 0, flat plates, no glass, no neon, no shadow-glow — elevation is plate + hairline
  • The four signal hues are CVD-validated (ΔE ≥ 37) and never decorative
  • Reduced motion stays fair: tells crossfade to the same steady state; windows never change

A UI that withholds all color until the corridor turns hostile — the identity is the thesis.

07 · the tech
Deterministic core · enforced budget

A real 3D game, proven by tests

The sim owns everything

  • Fixed-timestep TypeScript core: movement, door FSM, entity schedules and hitboxes, oil economy, scoring
  • Golden-trace tests: double-run identical state, seeds ignored, source scan proves zero Math.random in the core
  • Raw Three.js scene graph driven by the sim; React renders HUD and kiosk screens only

Perf budget, enforced not aspirational

  • Merged-room scene: ≤ 7 draw calls per room, 150 global cap — asserted over 24 doors × 2 variants × 3 quality tiers
  • One lantern spotlight + at most two event lights; zero shadow maps at any quality
  • All art procedural canvas (wood grain, plaster, tile, numerals); all sound WebAudio-synthesized — original by construction

Pointer-lock WASD + mouse + E, gamepad on the attract screen, FastAPI + SQLite leaderboard with server-validated scores — and the game runs fully with the backend down (localStorage mirror).

08 · the llm firewall
AI where it helps · absent where it would hurt

The LLM writes flavor. It never touches the game.

Flavor only

Local vLLM on the LAN (keyless) writes lore cards, death epitaphs and run-card lines. Output is display-only DOM text — never parsed back into game state.

Hard firewall

0.8 s timeout, one request at a time, a busy slot never queues — it degrades instantly to 32 hand-authored canned lines per kind. Canned text is first-class content, not an error state.

Zero paid APIs

The game is 100% playable and fully scored with the LLM down. Dependency and scope audits confirm no paid-API reference anywhere in shipped code.

The sim never reads LLM output. That sentence is a test, not a promise.
